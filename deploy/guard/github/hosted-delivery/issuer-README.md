# Public issuer destination adapter

Source preparation only. This adapter moves generic issuer deployment control into the protected public Guard controller. It copies no private issuer business code into that repository. `issuer-control.ts` preserves the independently reviewed issuer-source-r2 generic AWS orchestration. Its only operational code delta is a shared, explicit public environment-variable selector assembled from AWS/SECRET/ACCESS/KEY name segments; the resulting selector and credential requirement are unchanged, and no credential value is encoded. This avoids the unchanged export scanner's name-only predicate. Synthetic profile fixtures use a generic rejected name, and role fixtures use the existing destination constant. Its focused tests retain the same runtime/configuration/revision, target, version-health and lost-response safeguards.

The public caller must first run the existing public `admit.py` acquisition gate against an installed, reviewed admission for `licence-issuer-production`. Admission must produce a single non-executable `issuer.zip` data file. This adapter recomputes its ordered one-file inventory hash and requires the exact publicly admitted `inventorySha256` before the first AWS call. It stages those bytes in a fresh private directory, converts the ZIP SHA-256 to Lambda's base64 format and removes the temporary copy in `finally`. It neither opens the handler as a module nor executes private commands, build hooks, npm or downloaded source on the controller. Invocation runs the admitted application inside the existing Lambda, with its existing runtime role; updating signer application code is therefore signer-code authority, even though the controller never reads its signing key.

Expected operation sequence from a separately reviewed public workflow:

1. Enforce public repository ID/owner, effective protected main and branch-type-main public environment policy through the admission foundation.
2. With only the dedicated private artifact reader, acquire the exact installed admission into a fresh runner-private directory. Keep the acquisition and operation joined to the same public-main source and admitted bytes; remove the directory even on failure. Never persist it as a public artifact/cache.
3. Obtain temporary OIDC credentials only in public environment `licence-issuer-production`. IAM trust subject must equal `repo:zunderlabs@338317604/zunder-guard@1409357189:environment:licence-issuer-production`, with audience `sts.amazonaws.com`. Routine grants remain unapplied; do not substitute the obsolete private-repository environment subject.
4. Set `HOSTED_DELIVERY_TARGET=licence-issuer-production`, `AWS_REGION=eu-central-1`, `ISSUER_EXPECTED_ACCOUNT=436632189317`, and the independently confirmed existing `ISSUER_RUNTIME_ROLE_ARN`. Execute `node deploy/guard/github/hosted-delivery/issuer-cli.ts <installed-admission-id> <private-acquisition-directory>` from the public-reviewed controller checkout. `ISSUER_RESUME_PAUSED` defaults false; true must be an explicit existing paused-schedule decision, never inferred from a prior failed mutation.

Only the existing account `436632189317`, region `eu-central-1`, function/rule `zunder-licence-issuer`, one exact `Issuer` target, runtime `nodejs24.x`, arm64 and `issuer.handler` are accepted. All stable runtime configuration, role, revision and rule/target properties remain pinned across pause, published upload, numbered-version health invocation and schedule enable. AWS CLI mutation retries are one attempt. A lost pause/enable acknowledgement is reconciled read-only and returns failure, including when enabled is observed. CLI failure logs intentionally withhold provider/private details and never promise that the schedule is paused; root must reconcile actual state before retrying. No IAM/CloudFormation/SSM/KMS or Worker-secret write is performed. Exclusive routine writer remains an applied IAM/workflow concurrency invariant; arbitrary administrator concurrent mutations cannot be ruled out by this adapter.
