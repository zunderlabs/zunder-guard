# Protected public controller: exact private-payload admission

**Source preparation only.** This is a minimal successor to the private hosted-delivery controllers after discovering that the private organization's Free plan cannot enforce the proposed protected-main/environment boundary. It does not weaken that boundary check or treat freely mutable private main as publication authorization. It implements candidate admission and a verify-only public workflow. `publish` fails closed: no deployment adapters, Cloudflare credentials or signer grant are installed here, and no deployment has been performed.

The reviewed trust boundary is protected public `zunderlabs/zunder-guard` main plus selected **branch-type main** public environments. The actual effective review/check/no-bypass rules and environment branch restrictions must be verified before enabling the reader grant. A `protected: true` API field alone does not establish those rules. The controller checks repository ID `1409357189`, owner ID `338317604`, current protected public main and platform `refs/heads/main`/branch dispatch. These IDs came from the release lead's authenticated public identity read; the source does not create or change repository/OIDC settings.

Private builds retain tests and artifact packaging, without Cloudflare, publisher App or signer credentials. The public controller reads their accepted artifact strictly as data. It does not check out private source, run private npm/build hooks, import downloaded modules, execute private helpers or workflows, or upload private payloads into public logs/artifacts/caches. The reader is Python standard library, matching existing Guard distribution helpers; it introduces no framework or third language. JSON/parser/API errors are sanitized before reaching public logs. Files are written without executable permission beneath a fresh runner-private directory and removed even on failure. Receipts contain only admitted opaque identities/hashes and `applied: false`.

## One reviewed admission per exact payload

Place a strict schema-1 JSON file at `hosted-delivery/admissions/<id>.json` through ordinary public-main review. There are no installed candidates in this source packet. Dispatch accepts only that existing ID and its recorded target; it cannot supply source, artifact, destination configuration or controller path. This normal source review replaces unavailable private protection; it does not introduce another per-job approval gate.

Exact fields (the validator rejects unknown fields):

| Field | Meaning |
| --- | --- |
| `schema`, `id`, `target`, `kind` | `1`, safe fixed admission ID, one offered target, `website`/`customer-worker`/`licence-issuer` |
| `privateRepository` | `{id, fullName: "zunderlabs/zunder"}` from authenticated repository metadata; no invented ID |
| `sourceCommit`, `sourceRef` | Reviewed full 40-hex private source SHA and `refs/heads/main` |
| `producer` | `{workflowId, workflowPath, workflowBlob, runId, runAttempt, jobName}`: exact registered workflow ID/path, reviewed Git blob SHA at that source, immutable run ID, latest successful attempt, named successful build/check/package job |
| `artifact` | `{id, name, digest}`: exact GitHub artifact ID/name and API `sha256:<64hex>` digest |
| `inventorySha256` | SHA-256 of compact JSON of the sealed delivery manifest's ordered `{path,size,sha256}` file inventory; ASCII safe paths only |
| `config` | `null` or `{path, sha256}` binding exact artifact configuration as data; mandatory for customer Worker |
| `releasePin` | `null` or `{path, sha256}` binding exact website release-pin data; mandatory for website |

These opaque private source/workflow/run/artifact identities become public metadata if a real admission is merged. **That disclosure must be explicitly accepted before merging real candidates.** Private code/customer data, payload bytes and secret values are not disclosed. None has been placed in this template. Populate all values from authenticated reads and review; fixtures are synthetic negative-test inputs, never candidate or release acceptance evidence.

The reader rechecks repository identity, registered workflow metadata, the reviewed producer workflow blob at the admitted source, successful push-main run/latest attempt, producing job and exact artifact metadata. The API digest must match the downloaded archive; manifest schema 2 must bind the same source/run/attempt/workflow/ref and every regular file must match the publicly admitted inventory. Unadmitted files, symlinks/special files, unsafe paths, excessive sizes, source/job changes and a rerun appearing during acquisition fail closed. Workflow review must establish a branch-main-only build trigger and source checkout: a self-asserted `sourceRef` inside the private manifest is not independent GitHub branch authorization. Private current-main freshness is not the trust authority.

The archive download follows only its short-lived HTTPS GitHub artifact redirect to expected GitHub-managed artifact hosts; the installation token is not forwarded. The API documents the redirect but not an exhaustive host allowlist: an unknown host fails closed and must be reconciled in normal controller-source review, not bypassed.
