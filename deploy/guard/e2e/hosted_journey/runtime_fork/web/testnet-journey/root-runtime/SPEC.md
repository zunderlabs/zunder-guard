# Root-only staging memory supervisor (implementation contract)

Scope: root executes a reviewed Node TypeScript module from its existing coordinator. This is not a website module, HTTP service, browser bridge, shell script or autonomous release runner. No production/mainnet action, order, approval, funding, arbitrary transfer, custody retrieval or infrastructure outside existing staging controller. Root-reported genuine email recovery and fresh production email-recovery PASS (not signed-candidate activation) are separate evidence; this module does not read that email or inherit that PASS.

## Public staged API and custody

`createRootRuntime(config)` requires exact opt-in, clean diagnostics/environment and root's hash-bound trusted Node/Python/AWS executables plus exhaustive reviewed source manifests. It generates fresh merchant/Ed25519 seed/three distinct tokens only when root calls it. Original preparation/custody admission is explicitly root-configured, maximum60minutes from creation, never refreshed. No external writes precede plan binding; provision permanently tightens effective write deadline to min(original, actual approved20minute plan.end). All ordinary children/return/nonce gates share that tightened deadline; existing separately approved cleanup retains its own bounded cleanup lease. No generation happens on import or in offline tests. Private material is held in a closure; root gets only merchant/public issuer key and public status. No private getters, logs, files, environment values or command arguments.

Root builds/packages with public identity, reviews resulting exact artifact/plan/draft receipts, then calls staged methods. The module launches only existing pinned provision, issuer and purchase receivers with fixed argument construction and bounded stdin. Root continues owning owner SSM custody through the existing exact provider; this module adds no SSM reader/writer. New merchant persistence is not implied: process/machine death loses memory, and root must separately review any persistence contract.

Custody is retained through normal/failed child outcomes and deadline. Deadline forbids new writes and moves to HOLD; it does not erase material or terminate the supervisor. Unknown outcomes immediately stop all owned child groups, permanently stop write methods and require root read-only reconciliation. An awaited hold cannot guarantee against SIGKILL/OS failure; root keeps the host/process alive. No global restart ledger or cross-process protection is claimed; exclusive durable public run claim and root sole-writer reservation are mandatory.

API phases: `publicIdentity()`; `provision(publicPaths)`; `startIssuer()`; `purchase(publicPaths)`; `stopChildren()`; `armReturn(publicReturnPolicy)`; `returnOnce()`; `reconcileReturn()`; `cleanup(publicPaths)`; `dispose()`. Public status/receipts may be read at any time. Source/artifact/child metadata validation failures create no network action. Root may stop and inspect between phases. No root-provided private callbacks or arbitrary child commands.

## Process/source boundary

Manifest files and public config are owned0600 regular canonical files beneath owned0700 immediate parents; bounded, no symlinks/hardlinks. Exact SHA pins bind raw bytes. Source manifest enumerates every expected source file and trusted executable hash. Caller cannot add a child entrypoint or change argv. Runtime performs source verification before generation and each child launch. Dependency/runtime trust is explicit: lockfiles and source are pinned; reviewed installed Node/npm/Python dependencies are prerequisites, not authenticated by merely naming package-lock.

Child environment is allowlisted from scratch. Refuse parent diagnostics/preload settings and active diagnostic execArgv; no NODE_OPTIONS, PYTHONPATH, arbitrary AWS endpoint override, venue/issuer/inbox secrets or tracing. Existing provider's approved AWS config/profile and inherited credential resolution are handled through reviewed root configuration, not copied arbitrary environment. No shell. Each child gets a new owned process group, stdin pipe and bounded captured output. Persist only sanitized fixed outcome/exit/status/hash facts. Capture raw secret-bearing child streams only in bounded memory and discard; never include them in thrown errors. Deadline/stop terminates only owned group, verifies group death; unknown write-bearing outcome latches HOLD. Cleanup children and issuer stop are still permitted while held; no automatic retry.

Root arms a public policy only after child processes are confirmed dead and their durable purchase output identifies exact successful checkout payment. Policy binds runId, merchant, funded owner N `0x0d708cfc4316b58f4ab00ee641a54baacc89cb14`, canonical token, explicit amount, checkout payment/ledger hash and exact short window. No default amount, fake checkout quote or automatic full-balance return. Decimal strings use bigint micro-USDC, positive amount<=exact received payment and355.61. Independently read both account ledgers to confirm that payment, and merchant clearinghouse withdrawable balance/current role/account model and canonical spotMeta before signing. Unknown or unproven perps balance/account model refuses; no spot/perps bridging.

Return only canonical `HyperliquidTransaction:SendAsset` typed data, domain chain421614, hyperliquidChain Testnet, signatureChainId0x66eee, merchant signer, destination N, sourceDex/destinationDex/fromSubAccount all empty, exact canonical USDC token and explicit amount. One signature and one POST to fixed testnet `/exchange`, no redirects/retry. Durable intent and irreversible latch BEFORE signing or any write request; signing failure consumes the attempt. Recheck identity/window/nonce before and after awaits. Responses are not transaction proof. Bounded independent merchant AND owner real ledgers must match one exact return hash and balances/fees must reconcile. No fee-free guarantee. Unknown/rejected outcomes never unlock another signature.

Any unknown child/signature/write outcome permanently latches HOLD and forbids all future signing, including return. Reconciliation may establish facts but never clear this latch. Operation admissions are serialized and consumed before awaits; maximum one apply, issuer, purchase and return. Deadline stops owned child groups.

Root authorizes exactly one actual proceeds return: the entire independently observed fresh/exclusive merchant balance must be<=355.61, no top-ups/other incoming, and amount+independently evidenced fee<=that balance. Explicit prearmed expected-fee evidence and fee/total-debit ceilings (maxDebit<=355.61) are required; SendAsset has no venue-enforced fee ceiling. Unknown fee/account model refuses admission. Trading userFees is not transfer-fee evidence; activation fee cannot be guessed from another network or silently subtracted. A post-transfer fee mismatch is HOLD, never an automatic repair.

Read-only reconciliation may poll at most3times with250ms waits and bounded bodies. Accepted-but-unconfirmed is HOLD; later explicit read-only reconciliation may establish proof. Expected merchant debit is return amount plus observed fee, owner credit must equal exact amount; no open positions/orders/account-mode uncertainty or concurrent root actions are allowed. Ledger/balance disagreement remains HOLD.

Cleanup invokes only existing exact-journal controller cleanup; expired launch does not authorize new apply. Dispose refuses while children live, unknown state or unreconciled merchant funds remain. Empty proof permanently closes every ordinary write admission. Disposal rereads final funds after child/cloud cleanup; stale earlier proof cannot authorize key destruction. Explicit root disposal after known no-payment/no-funds or proven return and confirmed cloud cleanup drops references/buffers best effort; no guarantee V8/ethers/core-dump zeroization. Public receipts survive; secrets never do.

## Offline verification/review

The protected path calls `createRootRuntime(config, originalParentGate, originalKeeperMetadata)`. Both optional arguments must be present together. Before the existing generator, a fixed source-pinned Darwin probe validates the original stable Python parent, immediate Node keeper, reviewed source/runtime, memory protection and original anonymous FD3 identity. The original keeper gate retains its maximum 60-minute clock; the same admission subsequently tightens to the existing purchase plan's maximum 20 minutes. The receiver cannot renew either clock. Ordinary children never inherit FD3; only the fixed public read-only probe does.

`storePurchaseInputs(bindingRef)` retains the successful exact public binding privately after its three acknowledged writes and metadata/tag readbacks. `receiveCompletedPurchasePublication(expected)` consumes its claim before awaiting, matches that binding and the originally admitted challenge/controller, rechecks the real parent, then reads exactly one bounded sorted ASCII frame through EOF from the original FD3. A saved file cannot enter this path. Parsing or a failed receive does not prove payment. UNKNOWN permanently holds writes and retains merchant custody.

After an actual received publication, `armReturn(policy)` accepts a pinned receipt only when its raw bytes match that previously consumed frame. Its amount, token, nonce and ledger hash must match the live publication. The existing independent two-account venue ledger/balance checks, fee evidence, one-use signer and return reconciliation remain mandatory and unchanged. The completion message supplies public receipt hashes; it does not fabricate legacy broker flags or native acceptance evidence.

The fixed Python probe and launcher belong to the coordinator source. Local tests cover inert bindings and real harmless public pipes/child inheritance; they do not generate merchant credentials, authenticate the live parent, purchase, issue a licence, return money or establish end-to-end acceptance. Fresh independent review and real coordinated execution remain required.

Pure state/decimal/policy/typed-data validators and injected fake transport/process/crypto tests, fixed inert fixtures only. No fresh key generation, actual signatures, cloud/venue calls or credential reads in author tests. Test mismatch, expiry across awaits, unknown latch, post-sign expiry, body/response bounds, exact manifest/argv/environment, process group termination, ambiguous ledgers, fee/balance mismatch, read-only reconciliation and disposal refusal. Frozen source and fresh independent risk/security review are required before root executes.
